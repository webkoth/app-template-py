# Что нужно этому приложению

Этот файл — запись решений о проекте. Агент заполняет его при установке и
поддерживает дальше.

**Агенту:** задавай вопросы ниже по-русски, продуктовым языком, и записывай
ответы сюда по ходу. Не начинай работу над функциональностью, пока не
заполнены разделы «Приложение» и «Первая версия».

**Владельцу:** это запись того, что решили про твой проект. Если здесь
что-то неверно — скажи: агент считает этот файл источником правды.

Ячейки ответов держат `_не отвечено_`, пока вопрос не задан, и `н/д`, когда
вопрос к этому проекту неприменим. Разделы не удаляются, даже если все их
строки — `н/д`: другие документы ссылаются на них по названию.

**Состояние установки:** `не начата`

Значения: `не начата`, `идёт`, `завершена ГГГГ-ММ-ДД`. Строкой, а не
HTML-комментарием: этот файл читают с экрана `/docs`, а react-markdown
показывает комментарии как обычный текст — легенда выглядела там мусором.

## Решает агент — у владельца не спрашивать

Владелец отвечает за продукт, не за инженерию. Это решения агента:

- структура файлов, имена, состав компонентов, границы модулей;
- библиотеки в рамках стека;

  правил;

- вёрстка и композиция экранов внутри правил интерфейса.

## Что приложение умеет

Агент обновляет таблицу при каждом добавлении или удалении возможности.
Каждая строка держит ровно одно состояние:

- `included` — есть и работает;
- `available` — частично есть, но пользоваться нельзя; в примечании сказано,
  чего именно не хватает;
- `absent` — этого в проекте нет. Строить только после просьбы владельца;
- `removed` — удалено сознательно при установке. **Не возвращать.**

Возможности без строки считаются `absent`. Добавляй строку, а не догадку.

| Возможность | Состояние | Примечание |
|---|---|---|
| Вход по логину и паролю | `included` | scrypt из stdlib, ограничение попыток по логину и по адресу, выровненное время отказа |
| Первая учётная запись из переменных | `included` | `APP_BOOTSTRAP_*`, пара по умолчанию admin / admin; заводится только при пустой таблице. Пара известна всем, у кого есть шаблон, поэтому на боевом контуре под ней не работают: заводят свою учётную запись и отключают эту. Предупреждение висит на первом экране, пока вход идёт под дефолтной парой |
| Смена пароля в приложении | `absent` | сменить пароль своей учётной записи нельзя — только завести новую и отключить старую |
| Роли viewer / editor / admin | `included` | `require_role` на каждом маршруте, кроме шести перечисленных в `AGENTS.md`; правило сторожит тест `backend/tests/api/test_route_guards.py`. Отказ пишется в серверный лог |
| Отключение учётной записи | `included` | закрывает вход и отзывает уже выданные сессии; удаления пользователей нет намеренно |
| Журнал аудита | `included` | пишется той же транзакцией, что и мутация; экран для admin |
| Образцовый раздел «Расходы» | `included` | учит цепочке «форма → правило предметной области → база → журнал аудита». **Удалить**, когда появится первая настоящая фича; от «Таблиц» не зависит — образцы учат разному и уходят порознь |
| Образцовый раздел «Таблицы» | `included` | учит цепочке «файл → очередь → расчёт → результат»: `backend/app/features/datasets/`, экраны `/datasets` и `/jobs`. **Удалить** тогда же и на тех же условиях, что «Расходы». Решение оставить оба принято владельцем 2026-09-02 |
| Стартовая страница | `included` | что это за приложение, ссылки на разделы. Когда появится первая настоящая фича — `/` **переписать** под неё. Саму страницу не удалять: маршрут несущий |
| Страница дизайна `/design` | `included` | все установленные компоненты в рабочих состояниях и примерка пяти тем. Удаляется целиком, когда оформление выбрано; `frontend/src/lib/design/` остаётся |
| Готовые темы оформления | `included` | пять тем, применение командой `npm run theme -- <имя>`; по умолчанию синяя |
| Правила и команды в интерфейсе | `included` | маршрут `/docs`, читает файлы репозитория с диска через `/api/meta/docs` |
| Ежедневная резервная копия базы | `included` | cron заводит провижинер при установке: 14 дней плюс по одной на 1-е число месяца. Свежесть копии сторожит конвейер `backup.yml` |
| Отслеживание ошибок внешним сервисом | `absent` | решено не брать: обработчик в `core/errors.py` и `/logs` |
| Загрузка файлов и медиа | `included` | файлы — да, медиа — нет: тип проверяется по содержимому, и проходят только CSV и XLSX; картинку и PDF загрузка отвергает намеренно, расширение списка — отдельное решение. ## Известный технический долг

Не мешает работать, но однажды придётся закрыть. Здесь, а не в головах.

| Что | Когда всплывёт |
|---|---|
| Счётчики попыток входа живут в памяти процесса | Перезапуск их обнуляет. Рабочий процесс внутри uvicorn один — он и есть счётчик контура; при нескольких понадобилось бы общее хранилище. Слово «воркер» здесь значило бы именно его, поэтому оно убрано: воркер очереди — другой процесс, HTTP он не обслуживает и входов не считает. Ожидание «вопрос встанет вместе с очередью» закрыто спекой слоя данных: очередь пришла, вопрос не открылся |
| `audit_log.actor` — логин строкой, без связи с `users` | Появится переименование логинов — журнал разойдётся с реальностью |
| Провижинер общий с `app-template-ts` | Своей копии `scripts/server/` здесь нет намеренно. Понадобится провижинеру разойтись по языкам — он переезжает в отдельный репозиторий, общий для обоих шаблонов |
| Загруженные файлы не попадают в ночную копию | Копия снимает базу, а не диск. Производное — строки, сводки, обученные модели — лежит в базе и переживает; исходник придётся загрузить заново. Всплывёт в день, когда файл понадобится второй раз |
| `<слаг>-status` и `<слаг>-logs` не видят воркер очереди | Оба зовут pm2 по одному имени — `<слаг>`. Скрипты генерирует провижинер на каждый слаг отдельно, поэтому правка провижинера не чинит уже заведённые контуры, а править `/usr/local/bin` нужен root. Обойти через `sudo -u deploy … pm2` тоже нельзя: учётке `ops` разрешён закрытый список из четырёх команд. Что делать вместо этого — в `docs/commands/status.md` и `docs/commands/logs.md`: живость очереди смотрят на экране «Задачи», процесс — в логе последней доставки |
| Воркер очереди один | `SKIP LOCKED` рассчитан на любое их число: одну задачу получает ровно один воркер, и это гарантирует база. Второй добавляется строкой в доставке — но без нагрузки, которая бы этого требовала, он удваивает эксплуатацию задаром. Всплывёт, когда задачи начнут ждать очереди дольше, чем считаются |
| Признак живости воркера неточен в двух местах | `GET /api/jobs/health` читается как «очередь двигалась не дольше `JOB_STALE_AFTER_SECONDS` назад». Простаивающий воркер следов не оставляет вовсе и от незапущенного неотличим; сразу после постановки задачи есть окно около секунды, когда на исправном контуре признак говорит «не жив». Экран «Задачи» второе закрывает выдержкой, точным признак от этого не становится. Всплывёт, когда по нему возьмутся чинить контур |
| Каталог `uploads/` копит файлы прогонов | Сквозные сценарии загружают файлы, а `make check` сбрасывает схему базы e2e — строки о файлах исчезают, сами файлы остаются сиротами, и удалять их некому. Каталог в `.gitignore`, на контуре сценарии не идут: растёт он только на машине разработчика. Всплывёт объёмом |
| Обучение отбрасывает строки с пропусками | Сколько выброшено, уезжает в результат задачи и видно на экране, но заполнения пропусков нет — как нет и подбора параметров. Всплывёт на выгрузке, где пустая ячейка значит ноль, а не «неизвестно»: модель обучится на остатке и о смысле пропуска промолчит |
