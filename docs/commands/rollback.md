# /rollback — вернуть предыдущую доставку

**Сначала пойми, что именно сломалось.** Это две разные аварии:

| Что сломалось | Чем чинить |
|---|---|
| Экран, расчёт, отчёт | откат кода — эта команда |
| Данные (миграция удалила колонку, синк затёр) | восстановление копии, эта команда НЕ поможет |

Откат кода не отменяет миграцию: если колонку удалили, её нет и после
отката, а старый код на такой базе не поднимется. Если авария про данные —
остановись и скажи: нужен дамп с сервера, каталог
`/home/deploy/backups/<слаг>/`, и **перед восстановлением обязательно снять
дамп испорченного состояния**, иначе разбирать причину будет не на чем.

## Порядок

1. `git fetch origin` и покажи последние доставки:
   `git log origin/main --merges --oneline -10`
   Точка отката по умолчанию — последний merge-коммит. Если аргументом дан
   коммит, считай точкой его.
2. Покажи, что уйдёт, и спроси подтверждение. Отдельно проверь миграции:
   `git diff <точка-отката>..origin/main --stat -- backend/alembic/versions/`
   Миграции в списке — предупреди, что откат кода их не отменит.
3. Откат — **возвратом изменений, а не переписыванием истории**:
   ```
   git switch main
   git pull origin main
   git revert --no-commit -m 1 <merge-коммит>
   git commit -m "revert: откат доставки <коммит>"
   git push origin main
   ```
   Форс-пуш в `main` запрещён: на репозитории параллельно работают
   несколько копий, и переписанная история ломает их все. Возврат даёт то же
   состояние контура и никого не ломает.
4. Дождись доставки: `sh scripts/wait-for-run.sh deploy.yml`
   Скрипт ждёт прогон именно за коммитом отката. Прежняя подстановка
   `gh run list --branch main -L1` в окне между push и созданием прогона
   отдавала ПРОШЛЫЙ прогон — тот самый, который и привёз аварию, — и откат
   объявлялся доехавшим, пока он ещё шёл.
5. Проверь живость и скажи пользователю, на каком коммите теперь контур.
6. Причину поломки чини на feature-ветке и доставляй обычным `/ship`.
