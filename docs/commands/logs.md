# /logs — логи контура

Аргумент необязательный: число строк (до 1000, по умолчанию 100).

`ssh <слаг>-ops sudo <слаг>-logs [строк]`

Именно алиас `<слаг>-ops`, а не `ssh ops@<адрес>`: установка заводит запись
`Host <слаг>-ops` со своим `IdentityFile` (шаг G), и обращение по адресу под
неё не попадает — ssh уходит с ключом по умолчанию и получает
`Permission denied` при живом и настроенном ключе.

Отказ — сначала проверь, заведён ли алиас:
`ssh -G <слаг>-ops | grep -E '^(hostname|user|identityfile) '`. Нет
`hostname` сервера и ключа контура — алиаса нет, и это шаг G установки, а не
недостающий доступ. Алиас на месте — тогда да, публичную половину ключа
должен добавить владелец сервера.

Разбери вывод, а не вываливай его целиком: если видны ошибки, объясни
человеческим языком, что происходит, и предложи следующий шаг. Пользователь
этой команды — не разработчик, стек вызовов ему ничего не говорит.

## Воркера очереди здесь нет

`<слаг>-logs` показывает **веб-процесс**. Воркер очереди — второй процесс
pm2, `<слаг>-worker`, — в этот вывод не попадает: скрипт зовёт `pm2 logs` по
одному имени, `<слаг>`, и генерирует его провижинер на каждый слаг отдельно,
так что правка провижинера уже заведённые контуры не чинит. Обойти через
`ssh <слаг>-ops sudo -u deploy … pm2` тоже нельзя: учётке `ops` разрешены
ровно `<слаг>-status`, `<слаг>-logs`, `app-deploy-key` и `app-secret`, на
остальное sudo отвечает «not allowed to execute». Не трать на это попытку.

Про воркера смотрят другое, в этом порядке:

1. **Экран «Задачи»** — первое и обычно достаточное. Причину отказа воркер
   записывает в саму задачу, а не только в лог, и она видна в колонке
   «Причина отказа». Там же видно, движется ли очередь вообще.
2. **Лог последней доставки** — если воркер не поднялся вовсе. Доставка
   проверяет его отдельно и печатает либо `процессы pm2: <слаг> и
   <слаг>-worker (online)`, либо строку отказа с состоянием процесса:

   ```
   gh run view "$(gh run list --workflow=deploy.yml -L1 --json databaseId -q '.[0].databaseId')" --log | grep -E "процессы pm2|воркер"
   ```

   Это говорит о моменте доставки, а не о «сейчас».
3. **Собственный вывод воркера** — только у владельца сервера, из-под
   `deploy`: `PM2_HOME=/home/deploy/.pm2 pm2 logs <слаг>-worker --lines 50
   --nostream`. Проси это, когда первых двух источников не хватило, и
   говори, что именно ищешь.

Расхождение известное, записано в реестре долга `CHECKLIST.md`; состояние
воркера целиком разбирает шаг 3 команды `/status`.
