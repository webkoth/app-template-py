# /logs — логи контура

Аргумент необязательный: число строк (до 1000, по умолчанию 100).

`ssh <слаг>-ops sudo <слаг>-logs [строк]`

Именно алиас `<слаг>-ops`, а не `ssh ops@<адрес>`: установка заводит запись
`Host <слаг>-ops` со своим `IdentityFile` (шаг G), и обращение по адресу под
неё не попадает — ssh уходит с ключом по умолчанию и получает
`Permission denied` при живом и настроенном ключе.

Отказ — сначала проверь, заведён ли алиас:
`ssh -G <слаг>-ops | grep -E '^(hostname|user|identityfile) '`. Нет
`hostname` сервера и ключа контура — алиаса нет, и это шаг G установки, а не
недостающий доступ. Алиас на месте — тогда да, публичную половину ключа
должен добавить владелец сервера.

Разбери вывод, а не вываливай его целиком: если видны ошибки, объясни
человеческим языком, что происходит, и предложи следующий шаг. Пользователь
этой команды — не разработчик, стек вызовов ему ничего не говорит.
